Estimating effectiveness

0.1 From description to causal inference

All the analyses in previous chapters were descriptive or exploratory — they characterise populations, estimate rates, and describe drug utilisation. An effectiveness (or comparative safety) study takes a fundamentally different step: it attempts to estimate a causal effect of one treatment compared to another.

This is harder. Confounding — the systematic difference between who receives each treatment — is the central threat. In a randomised trial, random allocation ensures that confounders are distributed equally between groups. In observational data, we must adjust for confounding analytically, using tools like propensity scores.

The OHDSI approach to causal inference from observational data is the new-user active-comparator cohort design with propensity score adjustment and negative control calibration, implemented in the CohortMethod R package (part of HADES).

NoteFor epidemiologists

This chapter implements what Hernán and Robins call the “target trial emulation” framework: we specify the hypothetical trial that would answer our question (the estimand), and then use the observational data to emulate it as closely as possible.

NoteFor regulators and HTA bodies

The methods in this chapter align with the ICH E9(R1) estimand framework and the ENCePP Guide on methodological standards. The negative control calibration step is specifically designed to address the systematic error (residual confounding, outcome misclassification) that EMA flagged as the primary concern in RWE submissions.

                  writeSchema = "main", 
                  writePrefix = "greg_")


semaglutide <- getDrugIngredientCodes(cdm = cdm,
                                      name = "semaglutide")

t2dm <- getCandidateCodes(
  cdm = cdm,
  domains = "Condition",
  includeDescendants = TRUE, 
  includeAncestor = FALSE,
  keywords = c("type 2 diabetis mellitus", "T2DM")
)

acute_pancreatitis <- getCandidateCodes(
  cdm = cdm,
  domains = "Condition", 
  includeDescendants = FALSE,
  includeAncestor = FALSE,
  keywords = c("Acute pancreatitis")
)

# Build drug exposure cohorts (one per GLP-1 agent)
cdm$semaglutide_cohort <- conceptCohort(
  cdm         = cdm,
  conceptSet  = semaglutide,
  name        = "semaglutide_cohort",   # name of the cohort table in the CDM
  exit = "event_end_date",
  overlap = "merge")


# Build condition cohorts
cdm$t2dm_cohort <- conceptCohort(
  cdm         = cdm,
  conceptSet  = t2dm,
  name        = "t2dm_cohort"
)

cdm$ap_cohort <- conceptCohort(
  cdm         = cdm,
  conceptSet  = acute_pancreatitis,
  name        = "ap_cohort"
)

cdm <- bind(cdm$semaglutide_cohort, cdm$t2dm_cohort, cdm$ap_cohort, name = "study_cohorts")
TipCohortMethod uses a different connection approach

Unlike the DARWIN EU packages (CDMConnector-based), CohortMethod uses DatabaseConnector. Both ultimately connect to the same OMOP CDM, but you need to specify the CDM schema and results schema separately in the CohortMethod functions.

The target estimand

Before writing any code, state the estimand precisely (ICH E9(R1)):

Population: Adult T2DM patients initiating a GLP-1 RA for the first time, with 365 days prior observation and no prior GLP-1 RA use

Treatment: Semaglutide vs. liraglutide (one pairwise comparison shown; repeat for all pairs)

Variable: Time to first acute pancreatitis event (inpatient/emergency)

Summary measure: Hazard ratio from Cox proportional hazards regression on propensity-score-matched cohorts

Intercurrent event strategy: Hypothetical — patients censored at treatment discontinuation (gap >60 days), switch to other GLP-1 RA, or initiation of pancreatitis-associated drug

TipThe preference score plot is your most important diagnostic

Before matching, plot the propensity score distributions of the two cohorts on the preference score scale (which re-scales the PS to account for prevalence differences). If the distributions do not overlap substantially, matching is impossible for a large fraction of patients — you have an equipoise problem and your causal estimate will be extrapolating outside the region of common support.

Our study: After 1:1 matching, we expect the Love plot to show all covariates with SMD below 0.1. If several covariates remain above 0.1 after matching, consider switching to IPTW or adding interaction terms to the propensity score model.

1.1 Step 4: Outcome model (Cox regression)

1.2 Step 5: Negative control calibration

This is the step that distinguishes a rigorous OHDSI analysis from a conventional pharmacoepidemiology study. Negative controls are outcomes where we know (from clinical reasoning) that the exposure has no causal effect. If our analysis pipeline has systematic error (residual confounding, outcome misclassification, time-at-risk misspecification), the negative control estimates will not be centred on a HR of 1.0.

Our study: If the negative control estimates are systematically shifted above HR = 1.0 (suggesting our analysis over-estimates risk), this means there is residual confounding — semaglutide users are sicker than liraglutide users in ways our propensity score did not fully capture. The calibrated HR corrects for this bias empirically. A calibrated p-value above the threshold after this correction means the primary finding is not robust to systematic error.

Quick check: After running 75 negative control outcomes through the same pipeline as your primary analysis, you find that the median HR for negative controls is 1.28 (rather than the expected 1.0). What does this tell you?

A systematic shift in negative control estimates away from HR = 1.0 is the definition of systematic error in your analytical pipeline. Since negative controls are chosen specifically because GLP-1 RAs should have no causal effect on them, any deviation from 1.0 must be due to bias in the analysis — most commonly residual confounding (sicker patients in one group), differential observation (one group has more healthcare contacts and therefore more coded diagnoses), or immortal time bias. The EmpiricalCalibration package uses the distribution of negative control estimates to model this systematic error and correct the primary estimate and its p-value accordingly.

1.3 Step 6: Kaplan-Meier plot

1.4 Interpreting the hazard ratio

Quick check: Your calibrated HR for acute pancreatitis comparing semaglutide vs. liraglutide is 0.87 (95% CI: 0.71–1.06, calibrated p = 0.18). What is the correct conclusion?

A HR of 0.87 with a 95% CI of 0.71–1.06 means the confidence interval includes 1.0 (no difference). The calibrated p-value of 0.18 is above any conventional threshold for statistical significance. The correct conclusion is that we found no statistically significant difference in acute pancreatitis risk between the two agents. The point estimate is directionally consistent with a small advantage for semaglutide, but the evidence is insufficient to conclude a true difference exists. This is a clinically important null finding — it provides reassurance that both agents carry similar pancreatitis risk in real-world T2DM populations.

1.5 Exporting the results

You can export a summarised result with all the objects that you created from your different calculations, and then read that file in a Shiny App to show the results. The package for that is OmopViewer but visOmopResults and each package own functions allow for it too.
