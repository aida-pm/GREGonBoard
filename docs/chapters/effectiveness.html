Estimating effectiveness

1 From description to causal inference

All the analyses in previous chapters were descriptive or exploratory. They are used to characterise populations, estimate rates, and describe drug utilisation. An effectiveness (or comparative safety) study attempts to estimate a causal effect of one treatment compared to another.

Note

The standard is to perform “comparative” studies (one treatment vs. another) instead of comparing to no treatment. This is to more closely reproduce a clinical trial framework and avoid selection bias.

Assessing causality is the hardest task in pharmacoepidemiology. Confounding is the central threat. In a randomised trial, random allocation ensures that confounders are distributed equally between groups. In observational data, we must adjust for confounding analytically, using tools like propensity scores, but we are restricted to the variables available in the data.

The preferred approach to causal inference from observational data is the new-user active-comparator cohort design with propensity score adjustment and negative control calibration.

Tip

In your protocol, you used the ICH E9(R1) estimand framework to define your research question and objectives. Keep that framework in mind during this chapter!

2 Setup

In this example, we better work with the Eunomia dataset as an example instead of the omock data, because the number and variety of drug exposures available in the synthetic data are more broad in the Eunomia dataset. You can also download example datasets from the omock package, like the GiBleed dataset. The documentation of the package is here.

3 Example pipeline

This chapter uses a single comparative effectiveness question throughout:

Among people with T2DM who initiate semaglutide or tirzepatide, what is the comparative risk of acute pancreatitis?

The workflow is intentionally short:

  1. Build semaglutide and tirzepatide exposure cohorts.
  2. Intersect each exposure with T2DM.
  3. Use the first qualifying exposure as the index date.
  4. Exit follow-up at acute pancreatitis, death, observation end, or 3 years.
  5. Extract baseline covariates.
  6. Estimate propensity scores.
  7. Match on the propensity score.
  8. Estimate the hazard ratio with Cox regression.
  9. Repeat with IPTW as a sensitivity analysis.
  10. Plot Kaplan-Meier curves.
  11. Use negative controls to assess systematic error.
  12. Extract the final results.

CohortSurvival is used for the descriptive time-to-event/Kaplan-Meier part, while CohortMethod is used for propensity scores, matching, IPTW, and Cox regression.

3.1 Step 1: Define the study population

Our question is:

Among people with T2DM who newly start semaglutide or tirzepatide, does the risk of acute pancreatitis differ between treatments?

We use a new-user, active-comparator cohort design:

  • Target: semaglutide + T2DM
  • Comparator: tirzepatide + T2DM
  • Outcome: acute pancreatitis
  • Index date: first qualifying exposure date
  • Prior outcome: exclude people with previous acute pancreatitis
  • Follow-up: from treatment initiation until acute pancreatitis, death, the end of observation, or the end of the study risk window

The intersection with T2DM was created in the setup section. exitAtDeath() makes death an explicit censoring point for the exposure cohorts. CohortConstructor supports both cohort intersections and changing cohort end dates at death.

3.1.1 CohortSurvival

CohortSurvival can estimate Kaplan-Meier survival directly from the target and outcome cohorts. The target cohort defines who is at risk and the outcome cohort defines the event.

Code 
survivalResult <- estimateSingleEventSurvival(
  cdm = cdm,
  targetCohortTable = "study_cohorts",
  outcomeCohortTable = "ap_cohort",
  outcomeWashout = Inf,       # no previous AP
  followUpDays = 1095,        # 3 years
  censorOnCohortExit = TRUE,  # includes death exit
  strata = list("cohort_definition_id")
)

For this study, baseline variables should include information such as:

  • age and sex
  • T2DM history and duration
  • obesity and related metabolic conditions
  • previous pancreatitis or pancreatic disease
  • gallbladder disease
  • alcohol-related conditions
  • hypertriglyceridaemia
  • renal disease
  • cardiovascular disease
  • diabetes medications and other relevant drugs
  • healthcare utilisation
Important

Simple rule for covariates: use information measured before treatment starts.

3.2 Step 2: Estimate the propensity score

The propensity score summarises the probability of receiving treatment A (semaglutide) rather than treatment B (tirzepatide), given measured baseline covariates. CohortMethod::createPs() fits the propensity model. In current versions of CohortMethod, IPTW is also derived from the propensity scores.

3.2.1 CohortSurvival

CohortSurvival uses a weight column when estimating the Kaplan-Meier curve to account for the Propensity Score, so you obtained the weighted survival directly.

Code 
weightedSurvival <- estimateSingleEventSurvival(
  cdm = cdm,
  targetCohortTable = "study_cohorts",
  outcomeCohortTable = "ap_cohort",
  weight = "iptw",
  outcomeWashout = Inf,
  followUpDays = 1095,
  censorOnCohortExit = TRUE
)

3.2.2 CohortMethod

Code 
ps <- createPs(
  cohortMethodData = cohortMethodData,
  population = studyPop
)

computePsAuc(ps)

plotPs(ps,
targetLabel = "semaglutide",
comparatorLabel = "tirzepatide",
showCountsLabel = TRUE,
showAucLabel = TRUE,

Tip

Look for substantial overlap in the propensity-score distributions. Poor overlap means that some patients are very unlikely to receive one of the two treatments, so the comparison becomes dependent on extrapolation.

Quick check: If the two propensity-score distributions have almost no overlap, what problem does this create for a causal comparison?

3.3 Step 3: Adjust for confounding

Here we show two simple approaches:

  1. Propensity-score matching
  2. Inverse probability of treatment weighting (IPTW)

3.3.1 Propensity-score matching

Code 
matchedPop <- matchOnPs(
  population = ps,
  matchOnPsArgs = createMatchOnPsArgs(
    maxRatio = 1,
    caliper = 0.2, # adjust at convenience
    caliperScale = "standardized logit"
  )
)

balance <- computeCovariateBalance(
  population = matchedPop,
  cohortMethodData = cmData
)

plotCovariateBalanceScatterPlot(
  balance,
  showMaxLabel = TRUE
)
Note

After matching, baseline covariates should be reasonably balanced between semaglutide and tirzepatide.

matchOnPs() performs propensity-score matching and removes people who cannot be matched within the specified criteria.

3.3.2 IPTW

Code 
iptwPop <- truncateIptw(
  population = ps,
  truncateIptwArgs = createTruncateIptwArgs(
    maxWeight = 10
  )
)

Truncation reduces the influence of very large weights. CohortMethod supports IPTW directly in the outcome model.

Why might matching and IPTW give slightly different estimates even when both use the same propensity score?

They must produce exactly the same estimate because they use the same propensity score.

Matching focuses on creating comparable treated-control pairs, whereas IPTW uses the propensity score to weight the entire sample, so the resulting target populations can differ.

IPTW can give very large weights to patients with propensity scores near 0 or 1, while matching may exclude patients who lack suitable counterparts.

Any difference between matching and IPTW proves that the propensity-score model was incorrectly specified.

3.4 Step 4: Estimate the effect of treatment with Cox regression

The main outcome is time to first acute pancreatitis.

3.4.1 CohortMethod: Cox regression after matching

Code 
outcomeModel <- fitOutcomeModel(
  population = matchedPop,
  fitOutcomeModelArgs = createFitOutcomeModelArgs(
    modelType = "cox",
    stratified = TRUE
  )
)
Note

The main result is the hazard ratio (HR) for semaglutide versus tirzepatide.

  • HR < 1: lower instantaneous risk with semaglutide
  • HR = 1: no difference
  • HR > 1: higher instantaneous risk with semaglutide

CohortMethod uses Cox regression for time-to-event analyses and can fit the model after propensity-score matching.

3.4.2 IPTW Cox regression

Code 
iptwOutcomeModel <- fitOutcomeModel(
  population = iptwPop,
  fitOutcomeModelArgs = createFitOutcomeModelArgs(
    modelType = "cox",
    inversePtWeighting = TRUE,
    bootstrapCi = TRUE
  )
)
Important

A hazard ratio is a relative measure. It does not tell us the absolute probability of acute pancreatitis. The Kaplan-Meier analysis in the next step helps describe the absolute event experience over time.

Suppose the HR for semaglutide versus tirzepatide is 0.80 with a 95% CI of 0.60-1.07. Is it correct to say that semaglutide reduces acute pancreatitis risk?

Yes because the average effect is under 1.

No, because the confidence interval crosses 1, the threshold for signifcant difference of effect.

No, but because you need to add that reduces the comparative risk of pancreatitis.

Although you do need to word it as “comparative risk” because you are not obtaining a measure of the absolute risk of acute pancreatitis but the comparative risk of suffering from acute pancreatitis depending on the treatment you take!

3.5.2 CohortMethod

Code 
plotKaplanMeier(
  population = matchedPop,
  outcomeId = acutePancreatitisId,
  confidenceIntervals = TRUE
)

The two curves should be interpreted together with the Cox estimate. A small visual separation does not necessarily imply a clinically important difference.

3.6 Negative controls

A negative control is an outcome that you include in the analysis for which there is no plausible causal effect of the treatment, but which is recorded in the same healthcare data. Including negative control outcomes is good praxis to look for evidence of systematic error such as residual confounding.

Warning

Do not choose negative controls just because they are easy to find. They should be clinically unrelated to the exposure and outcome, while still being recorded often enough to be informative.

3.7 Extracting the results

The final extraction should contain only the results needed to report this study:

  • number of semaglutide users
  • number of tirzepatide users
  • number with acute pancreatitis
  • follow-up time
  • matched Cox HR and 95% CI
  • IPTW Cox HR and 95% CI
  • Kaplan-Meier estimates
  • negative-control estimates

For the survival results, CohortSurvival returns a summarised_result object that can be inspected or converted with asSurvivalResult().

Code 
# Survival results
survivalTable <- asSurvivalResult(
  survivalResult
)

# Main Cox estimate
mainEstimate <- data.frame(
  analysis = "PS matched Cox",
  estimate = coef(outcomeModel),
  lower_95 = confint(outcomeModel)[1],
  upper_95 = confint(outcomeModel)[2]
)

# IPTW sensitivity estimate
iptwEstimate <- data.frame(
  analysis = "IPTW Cox",
  estimate = coef(iptwOutcomeModel),
  lower_95 = confint(iptwOutcomeModel)[1],
  upper_95 = confint(iptwOutcomeModel)[2]
)

mainEstimate
iptwEstimate
survivalTable
Tip

For a study report, keep the extraction step separate from the analysis code. This makes it easier to rerun the analysis without changing how results are reported.

4 Exporting the results

You can export a summarised result with all the objects that you created from your different calculations, and then read that file in a Shiny App to show the results. The package for that is OmopViewer but visOmopResults and each package own functions allow for it too.

Code 
# Suppress small cell counts before sharing
minCellCount <- 5 

exportSummarisedResult(
  mainEstimate,
  iptwEstimate,
  survivalTable,
  minCellCount = minCellCount,
  path = here("Results"),
  fileName = "GregonBoard_survival_{cdm_name}_{date}.csv"
)
